# 生命核心强制加载与死亡延迟上限

Core settings保护页新增Force chunk loading，默认Off。仅生命核心提供，休眠不加载；ALIVE和DYING维持核心及连接Sable肢体加载。保护页显示状态及目标区块数。关闭开关、Release、明确删除核心或死亡清理完成释放自身申请；不解除其他生命体或模组的票据。

主体使用持久化Sable SubLevelLoadingTicket，注册sablelife:life_core，以CreatureId作为独立持有者。世界区域使用按CreatureId独立、带40Tick过期的强制Tick票据，每Tick更新世界空间主体包围盒覆盖的区块列；移动/旋转释放旧列，重叠生命体保持各自申请。并非加载Sable存储坐标。Sable主体保存票据，服务器恢复时重新验证核心设置/状态和连接关系，世界票据重建；已申请者优先分配限额。

每生命体最多256目标区块，全服务器最多1024个不同维度/坐标目标区块。Minecraft自身可能为目标加载相邻必要区块。超限停止主体申请并显示limit；死亡奖励位置可能单独完成结算。范围不使用Boss血条或Arena半径。

死亡清理期间维持必要加载，奖励位置的必要区块结算后释放，包括0延迟先移除核心的情况。显式关闭或删除核心会关闭死亡任务继续申请奖励区块的标志，保持按需结算。加载不会使关闭或暂停的服务器继续Tick。

Core Death delay上限0–60秒（1200Tick），界面和服务端一致。旧Core配置/复制或进行中的全身死亡任务超过上限时夹限，保留生命/死亡状态和0HP；若剩余时间本就短于60秒，不重置。肢体独立延迟与回血延迟范围保持原值。

验证：55项单测、133项现行专用回归通过，含7项加载/上限专项。覆盖默认Off/休眠、世界坐标边界（含负坐标）、移动跨区块、共区块独立释放、Sable票据保存与运行缓存恢复、死亡清理、核心删除、DYING时关闭和旧长延迟迁移；GUI scale2/3布局检查通过。

真实无玩家远离、真正关闭重开服务器、复杂主体分裂/旋转及多人场景仍在PLAYTEST_CURRENT.md等待实机验收。此前15项早期集成失败未归因完成，不计入通过结果。
