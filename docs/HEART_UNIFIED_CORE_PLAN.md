# Heart 统一核心与虚拟模块重构规划

日期：2026-10-02。基线：0.1.23-dev。状态：可行性审查与实施规划，尚未修改运行架构。

## 需求来源与结论

已读取用户引用的《战利品掉落对比》最后几轮完整消息。目标是 Heart 内点击 + 添加模块，模块作为数据存在；点击标记按钮进入临时标记模式，选择攻击范围或炮口；同类型可添加多个，分别配置。保留机械外观，能力随所在肢体移动、旋转和断裂。

结论：可以实现，无需改变 Sable / Aeronautics 的运动系统。现有代码具备服务端生命状态、Sable 连接链查询、位置和旋转转换、旋转碰撞箱、攻击伤害、断肢归属和延迟战利品等基础。主要工作是抽离执行逻辑、增加稳定标记引用和统一编辑界面；不是单纯替换菜单背景。

引用对话中的下载文件未直接取得；本规划依据已读取的消息内容和本地代码检查，不声称已读取那个文件。

## 架构

Heart 保留实体方块，保存生命、名字、Boss 血条、身体破坏总开关、无线时序，以及虚拟模块列表。模块首版建议上限 32 个，按 UUID 区分，同类型可以重复。创造模式直接添加，不引入安装芯片成本；生存可安装模块物品属于后续玩法。

每个 ModuleInstance 保存：UUID、类型、显示名、enabled、类型化配置、标记引用、触发条件、schemaVersion。冷却、前一帧位置等运行缓存独立于配置；不要把任意未校验 JSON 直接作为运行指令。

未知模块类型保留原始存档数据并禁用，避免升级或缺少扩展时删除用户设计。所有界面修改只在服务端验证后生效。

## 标记必须跟随所属肢体

每个 Anchor 保存维度、所属 Sable 结构 UUID、结构局部方块位置／局部坐标、点击面与局部法线、逻辑标记 UUID。世界位置和方向每次从该结构当前 pose 转换。

不能只保存相对于 Heart 的偏移：关节使手臂相对躯干移动、旋转，Heart 偏移不再代表手臂上的真实位置。Heart 与标记只需位于同一有效连接链，不必属于同一个刚体。

结构分裂、重新组装若改变结构 UUID 或 plot 坐标，需要显式迁移标记。使用结构变化事件／已有归属迁移路径并经测试确认；不能假设 UUID 永远不变。未能唯一恢复标记时暂停能力，提示重新标记，不能猜测一个位置继续攻击。

首版范围标记：两次点击选择两个方块，选区包含两个端点方块。端点必须在同一 Sable 结构，构成局部立方体，随结构变成世界旋转碰撞箱。跨关节攻击用多个独立选区／模块，后续可提供一个模块内多个区域。

炮口／喷火口标记：点击方块表面同时记录出口位置和面法线；将出口略向外偏移，避免生成在自身方块内部。以后增加第二方向点，但不强制首版两次点击。

近战范围除端点外还需绑定选区中的实际身体方块。范围里的普通方块被拆掉后，不应继续充当不可见攻击面；沿用“手的实际部分有判定”原则，结合存活方块占用与每刻扫掠判定。不可仅凭两个仍存在的端点认定整个空间仍是手。

## 临时标记流程

选中模块 → 点击标记 → 创建服务端标记会话，关闭编辑界面 → 屏幕提示选择点 A／B 或出口 → 显示预览 → 确认后保存并返回该模块。

采用临时交互模式，不强行给背包塞永久物品。标记模式拦截相关右键，避免误放置／使用物品。Esc 取消，明确超时；退出游戏、切换维度、失去创造权限、Heart 移除、模块删除或激活后自动取消。取消不覆盖旧标记；重新标记完成后原子替换。

服务端验证会话 token、模块 UUID、配置修订号、模式、点击距离／射线／遮挡、结构归属和休眠状态。不接收客户端任意世界坐标作为可信标记。两人编辑同一模块时拒绝过期提交，避免覆盖新配置。

## 触发条件

虚拟模块没有方块位置，不能照搬 hasNeighborSignal。

首版提供：持续启用、指定标记方块附近的实体红石信号、Heart 内部无线时序频道状态。后者直接读取逻辑频道输出，避免为了内部攻击控制再摆接收器。

现有 Heart 无线发射继续对接 Create 接收器驱动关节。若希望接受外部 Create 无线控制，需要另做接收型频道；当前发送频道不会自动成为接收器。

后续增加“感应模块检测到目标”“受伤”“低血量”触发源。时间间隔是能力执行节奏；无视无敌帧仍保留，不能误变成每刻无条件重复触发所有技能。

## 统一界面

Heart 主界面采用独立 Screen：左侧总览／模块／标记／无线控制导航；中间可滚动模块列表、+ 添加、名称、启用和状态；右侧显示选中模块的配置与标记按钮。复用现有铜色与紫晶风格。

伤害上限 1000、击退上限 100，沿用现有字段限制。提供直接输入、加减与单位，配置改动经服务端确认。战利品仍用物品样本格选择模板；统一主界面不要求把物品编辑也改成纯文字。

创造模式可查看，休眠时编辑；活跃时只读，保留已有允许实时修改的名字／Boss 血条／身体破坏开关规则。模块状态细分：未标记、有效、关闭、未加载、断开、锚点破坏、冲突／需重标。

列表、类型化配置、标记会话和预览用有大小限制的 NeoForge payload；现有固定无线数值页仍可保留当前菜单同步。不要把完整大列表每 tick 广播给所有玩家。

## 能力与战利品

近战、喷火、箭矢、脉冲复用并抽离现有模块的伤害、碰撞、墙体遮挡、散射和特效代码；声音、感应作为后续虚拟模块类型。模块之间共享同一 tick 的连接图／标记解析结果，限制选区、候选实体和扫掠采样规模。

断开或锚点破坏立即停止该能力；未加载暂停，不能误判为断肢，也不能发放战利品。首版断肢停用锁存，重新接回不自动恢复战斗；创造解除后可重新标记。

虚拟 Loot 分“整体死亡奖励”与“肢体奖励”。整体沿用 Heart 死亡奖励；肢体需要先明确肢体组，绑定某个刚体／连接的子结构组，不能仅用攻击范围方盒决定要清理哪些方块。

激活时保存肢体奖励配置，断裂确认后向 LifeLifecycle 提交带独立 group UUID 的一次性奖励快照。Heart 被删、区块重载、模块标记失效后仍应完成已经登记的断肢清理和奖励。直接破坏奖励锚点的规则与断肢统一，禁止既发方块物品又发模板奖励造成复制。

## 兼容与现有代码

保留现有 Melee / Flame / Arrow / Pulse / Sensor / Sound / PartMarker 方块、注册 ID 与 NBT。新虚拟模块先并存，旧存档不自动删除方块或转换行为。

抽离后实体方块与虚拟模块共用执行器。后续提供明确的“导入为虚拟模块”操作，预览标记与参数，导入成功后停用来源，防止两套一起执行；迁移前备份。不得将旧 Loot 内容当真实库存掉落。

主要涉及：HeartBlockEntity、HeartSettingsMenu／新增 HeartDashboardScreen、现有攻击与感应／声音 BlockEntity、SableBodyProbe、BodyOwnership、LifeLifecycle；新增 ModuleInstance/类型注册、AnchorResolver、MarkingSession、ModuleTrigger、ModuleExecutor 和网络 payload。

## 实施顺序与验收

1. 数据与统一界面骨架：增删、命名、重复类型、保存重载、状态和权限。先不启用攻击，不破坏已有 UI 入口。
2. 通用标记：单点／同刚体两点、面法线、取消与预览。验证手臂独立移动旋转、标记方块破坏、分裂与重组迁移；这是后续能力的前置门槛。
3. 虚拟近战：先打通一个端到端模块，实际占用方块、扫掠、三个触发源、无敌帧规则与伤害／击退上限。同类型两个模块不串配置。
4. 喷火与箭矢：出口位置／方向、墙体、末端半径、散射、冷却、断肢立即失效。已有已发射箭矢保留正常飞行，不凭空消失。
5. 虚拟感应／脉冲／声音：复用目标筛选、范围预览、自定义音频和事件触发。
6. 虚拟肢体与 Loot：先明确肢体组、验证一次性奖励快照与重载，再并入集中界面。
7. 旧模块导入与优化：参数一致、动作不重复，保留兼容注册和回退数据。

每阶段维持现有 80 项 GameTest 通过并追加相应测试。重点验收：不是只随 Heart 移动，而是随关节肢体旋转；跨结构两点被拒绝；断开立即禁用，卸载不触发奖励；双人标记不串线；旧存档不丢配置；直接拆锚点和重载不能重复出战利品。

本轮只规划，不启动客户端、不修改已有运行代码。下一步推荐先完成阶段 1–2，确认标记基础正确后再启用虚拟近战。
