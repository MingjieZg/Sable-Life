# 0.1.198 生命体清除崩溃修复

开发验证版，包含已验证的0.1.197 Epic Fight初步适配。正式稳定版仍0.1.193。

## 证据与原因

用户最新报告crash-2026-10-09_21.48.20-server.txt，运行Sable Life0.1.196、Sable2.0.5。错误为“Sub-level assembly attempted inside plot of already removed sub-level”，路径为SubLevelHeatMapManager.split/step/tick。不是显存耗尽或已证实的Copycat数量上限。

在隔离环境配置真实Sable的待拆分队列并标记源结构已移除，原0.1.197复现相同异常。该测试复现生命周期边界，不声称已复制用户完整整合包。

原清理逐格删除，每格触发方块更新及连通性拆分工作。Sable2.0.5的热图循环未在所有入口及每个拆分批次检查源结构是否已移除，可能继续用已关闭的plot发起组装。原异常被稳定复现后才修改。

## 改动

1. 对完全加载、所有非空气方块均归属当前生命体/部位清理组的身体，使用官方container.removeSubLevel(...REMOVED)，与Photomancy删除按钮相同。若安装已核对的工具枪0.3.6，则调用其SubLevelRemovalCoordinator，保留该模组的绳索、控制及约束清理步骤。无需将两个参考模组的实现源码搬入本项目，也不新增强制依赖。
2. 新增按chunk反向ownership索引，避免对每个身体反复扫描所有生命体/方块。载入、绑定、释放和清理保持索引一致；验证全部实际非空气内容后才整结构删除。混合归属/未归属方块、未完整加载或预算不足时继续按原有预算只删除目标记录。
3. 热图tick/step/split以及每次真正发起拆分组装前检查isRemoved，已移除的源不会继续工作。没有关闭正常拆分，也没有吞掉全部RuntimeException。
4. 整结构删除前清除已装配CBC炮体，保留0.1.196的炮体不残留行为。官方API负责物理、跟踪、区块卸载及存储删除。归属在移除回调完成后退休，维持自定义战利品/经验和防重复结算；死亡视觉有界保留。

生命体清除使用原子身体操作时，单身体可超过256格；完成该操作后消耗剩余本tick方块预算，其他清理继续在后续tick轮转。256格限制仍用于逐格后备路线，旧cleanLoaded/cleanPart调用语义不变。验证预算不足时直接进入后备，不反复耗尽预算而停滞。

## 验证

- 修改前原生复现1项确认相同异常：verify198-baseline-crash.log。
- 修改后7项清除专项：已移除源、监听器内途中移除、正常拆分、1024方块死亡、混合归属、部位隔离、索引载入后删除。
- 用户实际Copycats3.0.9和工具枪0.3.6作为隔离依赖运行；1024方块身体使用官方路径消失，死亡清除不新增材料掉落，自定义战利品只发放一次，后续20tick不重复。
- 279项默认GameTest、57项单元测试通过。
- 同时加载Epic Fight21.17.3.1、Copycats3.0.9、工具枪0.3.6、TaCZ/CBC的46项组合回归通过，含原生武器及上述清理检查；与默认重复，不能相加作为独立覆盖数。
- 另一个清理/武器组合39项通过。

证据：verify198-complete.log、verify198-all-compat.log、verify198-compat-verified.log。早期材料断言把组装前合法物品也算作死亡掉落，已将断言限定为死亡新产生物品；普通非生命体材料返还规则未改变。

## 限制与回测

没有修改用户客户端、配置、世界或删除用户文件。只读取最新崩溃报告，并把两个已安装JAR复制进隔离测试目录；第三方JAR、完整崩溃报告和个人路径不上传GitHub。

未在用户数百模组整合包中运行客户端渲染/长时间压力测试，不能保证该环境所有清除问题均已解决。请重点用原出问题的机械重复死亡消失，检查有没有新崩溃、材料掉落、炮体/部位残留及重复战利品。

0.1.198继续使用协议6；建议客户端/服务器同版本更新。Epic Fight仍仅已核对21.17.3.1的主手普通挥砍/连招，特殊技能/副手/充能未全面支持，详见EPIC_FIGHT_COMPAT_0.1.197.md。稳定版未提升。0.1.197导出及修改前源码ZIP保留。
