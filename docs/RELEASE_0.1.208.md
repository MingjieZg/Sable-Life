# 0.1.208 — 重生后多部件死亡清除修正

用户发现重生生命体再次死亡，只清理核心part。代码中的重生激活调用通用一次性BodyOwnership.capture，仅遍历核心当前getConnectedChain，随后ownershipCaptured=true。连接依赖尚未恢复或未被第三方蓝图hook重建时，其他真实创建的part可能漏登，死亡清除按归属索引工作，因而留下它们。现有0.1.206测试只覆盖单身体结构，不能证明多part完整清除。

重生完成及成功激活后，按BlueprintBuildProgress实际分配的身体UUID与每个蓝图方块位置补全新生命体归属。每块核对其所在身体UUID，不接管其他生命体，不按世界包围盒扫周围独立结构。空方块跳过，保存加载使用现有持久化ownership。之后死亡等待集合还合并全部已登记身体UUID，避免只等待核心连接链。原有分批清除、库存、奖励、记录预算和可选依赖保持。

这修复清除归属，不声称第三方关节的物理连接本身已经恢复；仍需整合包实测。绳索另一侧原本不在记录里的独立结构，不会因此被额外清理。

新GameTest构造真实两个身体的原生蓝图，重建时不提供连接actor，以复现归属捕获遗漏；验证新生命体登记两个part，ownership保存加载后再次死亡的等待集合包含两者，全部清理完成，而模板外金方块身体仍保留。用于模拟连接依赖缺失，不冒充真实第三方绳索/关节验收。手册revision60。开发版0.1.208，稳定仍0.1.200。

验证：最终构建、58单元、28重生/Arena/生命周期/清除GameTest通过，包含多part归属保存加载后第二次死亡。旧漏登残件不会自动补清，用户世界未操作。
