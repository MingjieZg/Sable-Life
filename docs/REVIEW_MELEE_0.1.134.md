# Melee 整体审查（0.1.134，2026-10-06）

本次为review，不修改正式实现、不提升版本。临时诊断源码与模板保存在backups/melee-review-0.1.134，日志为review-melee.log。

后续：0.1.135已修复旋转圆弧扫掠，并新增角度偏移和每次激活命中上限；空洞与生命体装甲转发两项仍待处理。

## 发现

### P1：旋转扫掠用弦代替圆弧，既漏打也误打

ModuleCombat.java:140–148：根据两次世界范围中心的线性插值计算contact，再插值旋转。长臂上偏离旋转轴的区域实际上沿圆弧运动，不能用两个范围中心连成的直线代替。

诊断用实际ContactBox判定复现：局部中心离轴7格、旋转60°、半径0.5的盒，圆弧中点有真实接触但当前扫掠不命中；弦中点没有真实接触但当前扫掠命中。中心一tick移动超过8格还直接丢弃历史，因此较长臂/较大Start distance的正常转动也可能被当成跳跃而不扫掠。

建议：保存所属结构上一次位置/旋转，在结构局部空间保存标记中心和偏移；每个采样插值结构姿态后再变换区域。区分真实瞬移与旋转引起的远端位移，不以范围中心位移独立认定瞬移。

### P1：生命体目标只有整机AABB，空洞也能掉血

ModuleTargets.java:52–65构造覆盖所有相连结构的总包围盒；ModuleCombat.java:148直接将其当最终碰撞箱；没有检查实际结构方块/碰撞形状。

诊断构造相连U形机器，在上半部中心空隙放置0.2格的碰撞盒。该位置实际为空气，但LifeTarget查询和ContactBox都通过，伤害路径扣除6点核心HP。

建议：总AABB仅做候选筛选；对生命体再检测相连结构的实际方块碰撞形状，确认有实体接触再结算伤害。

### P2：生命体装甲按核心所在结构计算，未使用真正命中肢体

ModuleTargets.java:82–83调用heart.damageAt(heart.getBlockPos(),amount)，丢失命中部位。ModuleArmor.java:10–17严格按传入的hit所属结构解析装甲。

因此，单独装甲肢体被击中时可能没有减伤；仅核心结构有装甲时，攻击无装甲肢体也可能错误继承核心减伤。此项为代码路径确认，未另搭建铰接装甲机器进行实测。

建议：生命体窄相检测同时返回实际命中方块/结构，用该位置调用damageAt，避免统一转发至核心位置。此问题与空洞误伤可共用实际命中查询修复。

## 现有行为与限制

- 两点Mark定义包含边界方块的长方体，必须同一结构；最大每轴32格。
- Damage默认6，Knockback默认1，Interval默认1秒，Start distance默认0；偏移沿第一个标记面，随结构旋转。Preview共用meleeCenter/halfSize，当前范围与偏移一致。
- 普通目标使用OBB/AABB分离轴检测，基本旋转盒会拒绝外围AABB空角；每模块、每目标独立命中间隔。正常持续触发及同tick重复调用不重复扣血。
- Interval当前按激活窗口计算：断信号会删除整个State，包括命中记录；即使同一个world tick重新供电也能再次伤害。已诊断复现interval=20 ticks时同tick断开再供电扣两次伤害。鉴于重启攻击窗口可视为新招式，这里记为需要明确说明的行为，不直接定为缺陷；如要全局严格间隔，应保留命中时间而只清除扫掠历史。
- 普通生存玩家、生物与其他生命体都可命中，排除创造/旁观/死亡与自身生命体；没有Melee专用目标分类选项。
- 效果只作用普通LivingEntity，ModuleEffects.apply明确排除LifeTarget，因此生命体不接受药水效果是主动设计限制，不误报为丢效果。
- Hurt Once给Melee一个tick窗口；Move set依照action时间窗供电。两者采用相同实际命中逻辑。
- 旧Melee实体方块的newBlockEntity/getTicker均为空，不是当前执行入口，本次不将旧代码当正在运行的攻击实现。
