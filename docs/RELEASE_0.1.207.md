# 0.1.207 — Arena 记录预算及诊断修正

开发测试版，稳定版仍为0.1.200；最低NeoForge21.1.235、协议7、Photomancy1.0.1可选依赖不变。

用户20个相连部件的结构被0.1.206通用「结构规模或数据量超过记录上限」拦住。代码确认旧限制将包围盒内空气也算扫描格，且所有规模/数据限制使用同一错误。截图不能证明具体触发哪项，不能直接归因为部件数量。

扫描预算32768→262144；实际方块16384→32768；方块实体1024→4096；单份模板内存估算1MiB→8MiB。部件仍32，实体仍256，世界记录仍32；新增所有模板总内存估算32MiB上限。保存加载使用相同字节预算，避免大记录保存后丢失。替换记录先减去旧模板再计算总额。捕获仅由服务器创造模式管理员发起，模板不进入客户端快照；增量建造预算不变。记录操作仍同步扫描，因此可能有一次性停顿，扩大预算不等于无限制。

超限提示和服务端日志现在给出具体项目、实际值、上限。若用户结构仍被拒绝，下一次可以准确判断扫描格、部件、方块实体或数据字节限制，而非继续猜测。

绳索另一侧按用户观察属于独立结构，现有死亡清除不额外删除它。记录继续使用与生命体组装边界相同的Sable getConnectedChain（通过actor dependencies），不会空间搜索绳索另一侧。未加入连接链的独立结构不会被新增捕获；第三方蓝图rope hook是否保留跨边界引用仍需真实整合包验证，本版不承诺绳索重连。

新增回归覆盖含大量空气的34×34×34包围盒、真实方块实体2MiB数据捕获与保存加载、世界总模板及单份数据上限、明确错误和边界值。完整记录/重生/激活/取消/清除既有回归继续验证。手册revision59同步新限额。

验证结果：58单元、27重生/Arena/生命周期/清除GameTest、真正无Photomancy的40GameTest与最终构建通过。原整合包20部件结构仍待用户回测，未操作用户世界。
