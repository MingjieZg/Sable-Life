# 最终验收要求：供附属 Mod 使用的统一伤害接口

记录日期：2026-10-19。用户明确要求：未来倾向由其他作者开发附属 Mod 桥接伤害；最终验收时必须交付明确、可使用的接口。

这是待实现/整理并验证的验收约束，不表示现有实验接口已经满足最终契约。现有接口与历史限制见 COMPATIBILITY_API.md；正式类名、方法签名及兼容策略以最终经过代码核对的文档为准。

## 统一责任边界

附属负责识别原模组的真实攻击、原始伤害、攻击节奏及归属，并提交实际命中资料。Sable Life 负责识别所属生命体与 Part，并统一处理可攻击条件、伤害修正/免伤、自适应防御、实际扣血、命中计数、击杀归属及死亡清理。附属不得通过直接修改核心生命值绕过这条链路。

精确命中应与生命体内部几何解耦；不能要求附属读取内部 Part 实现、依赖每格独立实体，或复制一套装甲和计分逻辑。内部结构、选中边框或精准命中实现变化，不应迫使所有附属重写伤害结算。

## 必须明确交付的契约

1. 公共 API 包、实际方法签名、参数单位与坐标系、调用线程/服务端边界，以及客户端提交的可信验证责任。
2. 命中入口：真实方块命中资料、世界坐标/攻击几何的支持方式及各自限制；世界位置与 Sable 内部存储位置的转换由谁完成，必须明确。
3. 请求资料：原始伤害、DamageSource、攻击者/所有者、弹射物等归属；可选字段、空值和无攻击者情况必须定义。
4. 攻击窗口/编号与去重契约：同一攻击何时只结算一次，持续攻击何时可再次命中；去重由接口还是调用者负责、作用范围、清理时机及上限均须明确。不能只提供一个语义含混的 UUID 字段。
5. 结构化结果：至少能区分实际扣血、免伤/阻止、重复命中、非生命体目标及请求无效/无法判定；提供实际生命值损失及可公开的目标身份。具体枚举以实现为准，不能把“没有扣血”一律解释为“没有发生有效碰撞”。
6. 命中与扣血分开：即使免伤，附属也能按原攻击规则决定是否消除弹射物、停止穿透或播放命中特效；不能靠扣血成功与否猜测碰撞。
7. 目标过滤：自身/友方、休眠/死亡、控制核心、无效 Part、未加载区块及几何预算不足时的行为，必须明确。
8. 外部原伤害事件、原生实体伤害、范围伤害、直接命中加爆炸等路径如何避免重复结算；不支持的实体专属效果、吸血/状态等不能声称自动兼容。
9. 公开只读查询/扩展事件的支持范围（如确有必要），避免附属直接依赖内部 HeartBlockEntity、Part 或 Mixin 私有实现。公开必要接口即可，不要求无条件暴露内部可变状态。

## 最终验收交付物与检查

- 一份以最终代码为准的接入文档：签名、示例、结果解释、限制、API版本及兼容/弃用策略。
- 至少一个最小、可编译的附属接入示例；说明构建依赖和可选加载方式，不以聊天中的伪代码代替交付。
- 覆盖直接命中、范围/持续攻击、重复回调、免伤时碰撞结果、Part/全身修正、实际扣血计数与击杀归属的接口级验证。
- 验证不加载特定第三方模组时也能正常加载核心公共 API，并说明客户端/服务端所需安装与版本条件。
- 最终报告明确列出已支持与未支持的桥接能力，以及未完成的检查。以上未完成前，不将实验 API 标记为最终稳定接口。
