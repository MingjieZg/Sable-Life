# Sable Life 0.1.452-review.3 服务端性能报告

开启视线检查时，0 秒目标记忆的平均 MSPT 从 16.62 降至 16.34，3 秒目标记忆从 2.95 升至 3.99。一次放置并激活 12 个简化核心的完整 tick 从 355.83 增至 409.69 ms。Walker 修复后的活动阶段平均 MSPT 从 4.31 升至 4.52，死亡清理阶段从 2.18 升至 2.80。两组测试对照的版本分别列在下文。

## 视线检查与蓝图放置

| 活动负载 | 指标 | 0.1.452 | 0.1.452-review.2 |
|---|---|---:|---:|
| 0 秒目标记忆 | 平均 / P95 / 最大 MSPT | 16.62 / 46.08 / 94.59 | 16.34 / 48.22 / 60.37 |
| 3 秒目标记忆 | 平均 / P95 / 最大 MSPT | 2.95 / 6.26 / 56.24 | 3.99 / 9.82 / 34.23 |

| 放置测量 | 指标 | 0.1.452 | 0.1.452-review.2 |
|---|---|---:|---:|
| 同一 tick 放置并激活 12 个核心 | 完整 tick（ms） | 355.83 | 409.69 |
| 单次原生蓝图放置调用 | 平均 / 最大（ms） | 6.77 / 21.88 | 5.60 / 18.24 |

每版各运行一次。场景包含 12 个单方块核心、96 个目标传感器和一名模拟生存玩家，按固定顺序测量 0 秒和 3 秒目标记忆，每档先预热 100 ticks，再采样 300 ticks。两档均开启视线检查，以相同的程序加入和移除遮挡。完整放置 tick 包含场景准备、蓝图导出、区块准备、放置和激活。单次放置调用耗时单独统计。

## Walker 活动与死亡清理

| 阶段 | 指标 | 0.1.452-review.2 | 0.1.452-review.3 |
|---|---|---:|---:|
| 装配 | 完整 tick（ms） | 290.45 | 198.40 |
| 装配 | 原生装配调用（ms） | 277.93 | 188.38 |
| 活动 | 平均 / P95 / 最大 MSPT | 4.31 / 11.52 / 22.33 | 4.52 / 8.08 / 38.46 |
| 死亡清理 | 平均 / P95 / 最大 MSPT | 2.18 / 3.77 / 48.38 | 2.80 / 4.15 / 59.74 |

每版各运行一次，使用 Let it Walk! 0.1.5 的原生六足演示机体。机体有 2 个活动核心和 18 个腿段。预热 50 ticks 后，分别采样 200 个活动 ticks 和 40 个死亡清理 ticks。两版均移除全部 18 个腿段，清理窗口的峰值均出现在致死命中的 tick。这组性能数据来自腿段保持加载的场景。

## 测试环境与范围

两组对照均在 Linux 上依次启动独立服务端，使用 Minecraft 1.21.1、NeoForge 21.1.235、Create 6.0.10、Sable Photomancy 1.0.1、Java 21 G1、3 GiB 堆和 4 个 JVM 活动处理器。视线测试使用 Sable 2.0.5，Walker 测试使用 Sable 2.0.6。MSPT 表示服务端每 tick 的毫秒数，P95 表示第 95 百分位。峰值为单轮观测，测试范围限于上表的场景和负载。
