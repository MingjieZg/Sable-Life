# Let it Walk 死亡清理性能对照

18 脚段双核心机械的死亡后观察中，443 留下 18 段，444 清至 0 段。正常活动和 32 只生命体场景的单次对照没有显示明显持续开销增加；这是本机小样本，不代表复杂服务器或所有规模都能保持满 TPS。

## 双核心 Walker

| JAR | 活动均值 / P95 / 最大 MSPT | 死亡窗口均值 / P95 / 最大 MSPT | 剩余脚段 |
|---|---|---|---|
| 0.1.443 | 1.735 / 2.629 / 11.931 | 2.189 / 3.103 / 31.371 | 18 |
| 0.1.444 | 1.806 / 2.578 / 14.992 | 1.495 / 2.470 / 35.199 | 0 |

每包单次运行：1 台六足 Demo Walker、18 个脚段、主体与其中一段各有核心，脚上启用 Contact Sensor，有地面支撑。暖机 50 tick，正常活动取 200 个 tick；随后通过箭矢命中处理入口击败主体，取 40 tick 死亡窗口，包含死亡时记录脚段和分批移除。旧包没有执行同等脚部清理，所以死亡窗口的均值不能当成单纯的算法加速。

## 蓝图生成与多只持续活动

| JAR | 32 次放置所在 tick 窗口 ms | 单次放置均值 / 最大 ms | 稳态均值 / P95 / 最大 MSPT |
|---|---|---|---|
| 0.1.443 | 400.668 | 2.863 / 12.386 | 2.399 / 3.078 / 11.236 |
| 0.1.444 | 427.318 | 3.057 / 16.498 | 2.437 / 2.981 / 11.635 |

同一原生蓝图场景：32 只单方块核心生命体、256 个 Contact Sensor，另有 1 个未激活模板。单批生成窗口包含导出、准备、区块、放置和激活，不是单只生命体的生成成本。暖机 100 tick 后采样 300 tick。为固定负载，在计时终点后归位并重置速度；这部分维护不计入上述窗口。

环境：Minecraft 1.21.1、NeoForge 21.1.235、Sable 2.0.6、Let it Walk 0.1.5、Create 6.0.10、Sable Photomancy 1.0.1、Java 21、2 GiB 堆。两包分别在独立游戏服务端串行运行，相同依赖与场景；MSPT 为 ServerTick Pre 至 Post 的实测窗口。只替换 Sable Life JAR。没有把这组测试视为长时间实战、完整武器矩阵或客户端 FPS 验证。
