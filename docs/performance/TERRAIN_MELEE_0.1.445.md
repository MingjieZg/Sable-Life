# 装饰物与近战地形破坏性能对照

32 只简化生命体的单次对照中，近战破坏关闭时，444／445 稳态均值为 1.619／1.685 MSPT；445 开启后为 1.860 MSPT。开启后同时处理地形的一次爆发窗口峰值为 **63.630 ms**，超过单 tick 50 ms；这组结果不能作为复杂机械战斗或稳定满 TPS 的保证。

每场景独立 JVM、串行运行一次。32 只单方块核心生命体，各有 1 个无实体目标的近战模块，另留 1 个未激活蓝图模板。近战框为 3×3×3，偏移 3 格。先运行 100 tick，在每个近战框内一次填入 27 个泥土方块，共 864 格；记录包含填入与处理成本的 20 tick 爆发窗口，再取后续 200 tick 稳态。旧版不支持新开关，请求后仍按关闭行为运行。开启与关闭处理的工作量不同，不能只比较耗时来判断效率。

核心碰撞破坏两行改为在各核心接触位置各放一格高草，共 32 格，近战破坏关闭。观察结束时，444 剩 32 格，445 剩 0 格；未应用植物保护预设。爆发窗口包含相同的放置操作，以及对应版本实际执行的检测、移除、邻居更新和掉落。没有隔离单独一次形状查询或方块移除的成本。

## 环境与边界

Minecraft 1.21.1、NeoForge 21.1.235、Sable 2.0.6、Create 6.0.10、Sable Photomancy 1.0.1、Java 21、2 GiB 堆。同一台 Windows 电脑、同一依赖与场景，只替换 444／445 实际 JAR；无 Let it Walk 或其他可选武器模组。MSPT 取 ServerTick Pre 至 Post 窗口。为固定负载，在计时终点后归位并重置结构速度，这部分维护不在窗口内。

这是每项一次、200 个稳态 tick 的小样本，存在 JVM 暖机、垃圾回收和系统调度波动，不能证明微小差值来自代码变化。场景不含复杂关节、持续补充地形、多玩家网络、第三方装饰物或客户端 FPS。工作预算限制扫描与破坏数量，但大范围或高速扫过仍可能留块。
