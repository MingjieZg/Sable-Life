# 近战碎块与方块掉落性能

32 个简化生命体时，新选项关闭的平均值为 2.153 MSPT，改前为 2.057；碎块和物品掉落同时开启为 3.473 MSPT，同时清理方块时单次最高 222.234 ms。本负载下开启选项会增加开销，新模块的两个选项默认关闭。一轮对照不能分离碎块和可拾取物品各自的成本。

| 场景 | 稳态平均／P95／最高 MSPT | 破坏峰段平均／最高 ms | 32次生成 tick 窗口 ms | 单次放置平均／最高 ms |
|---|---:|---:|---:|---:|
| before | 2.057 / 2.659 / 12.371 | 6.704 / 68.201 | 454.090 | 2.898 / 15.565 |
| after-off | 2.153 / 2.837 / 3.303 | 8.378 / 97.010 | 464.000 | 3.045 / 12.535 |
| after-on | 3.473 / 4.366 / 5.504 | 31.279 / 222.234 | 465.218 | 3.752 / 24.447 |

before 使用此前已交付的 0.1.450 aim-offset JAR；after 使用最终 0.1.450 候选（手册253）。三轮串行运行，均为32个单方块活动核心，各有一个近战模块，开启近战破坏，关闭机身碰撞破坏。after-on 同时开启两个新开关。在第100tick为每个攻击框放入3×3×3泥土，共864格；20tick峰段覆盖该事件，稳态采样第201–400tick，此时掉落物仍存在。

生成 tick 窗口包括场景设置、模板导出、区块准备、32次原生蓝图放置及激活，三轮均超过50ms；不能视为单只蓝图耗时或满TPS保证。单次放置计时不含后续激活。

环境：Minecraft1.21.1、NeoForge21.1.235、Create6.0.10、Sable2.0.6、Sable Photomancy1.0.1、Java21、2GiB堆，同一Windows机器。没有连接玩家，未测碎块发包和客户端渲染。MSPT计时从ServerTick Pre到Post，固定场景位置／速度的维护在终点后执行，未计入。每场景一轮，不代表最大容量、复杂机体或多人服务器结论。
