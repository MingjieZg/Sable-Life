# Sable Life 0.1.452

[English changelog](0.1.452_EN.md)

这是 Minecraft 1.21.1、NeoForge 的 `0.1.452-review.3` 预发布版。[0.1.450 源码更新说明](0.1.450.md) · [中文性能报告](../performance/SIGHT_AND_WALKER_0.1.452-review.3.md)

## 生存核心与索敌

- 服务端 `allowSurvivalHeartCoreTerrainBreaking` 默认开启。关闭后，生存生命核心的近战、激光和爆破继续对目标生效，保留地形和模块原有设置。
- 开启视线检查时，可以设定遮挡后保留目标的时长，范围 0–60 秒，默认 0 秒。目标传感器在标记位置检查玩家胸口和肩部，追踪激光瞄准随姿势变化的上胸。武器以实际发射口检查视线。
- 目标对齐与 Move Set 可绑定本核心的目标传感器。招式和武器继承目标时使用来源的原有到期时间，避免换招延长已经开始的计时。武器维持最后可见的瞄准位置，各自的视线条件继续决定能否开火。打开预览也不会更改核心当前的索敌记录。

## 蓝图、物品显示与复制器

- 原有 Photomancy `.nbt` 可直接放置。Sable Life 自动恢复生命核心模块、重映射标记，再回填物品显示的模型；官方 Photomancy 可继续使用。一份蓝图若超出工具的传输上限，可以把 `.nbt` 放到服务端目录后运行官方 `/sablebp load`。
- 支持分包的客户端可以接收大型物品显示快照。单个模型最多 900 KiB，单核心最多 64 项、合计 8 MiB，按未压缩传输大小和 NBT 读取用量计算。旧客户端可显示第一批。原始模型继续随存档保存。
- 数据复制器继续显示已用字节数与 2,000,000 字节的压缩上限。复制时检查数据能否被粘贴端完整读取。剪贴板保存在世界存档，按来源账户去重，每账户 64 MiB，每个世界 2 GiB。已有磁盘引用可继续使用。
- 管理员可用 `/sablelife clipboard status [<UUID|legacy>]` 检查用量，用 `/sablelife clipboard archive <UUID|legacy> <sha256>` 归档指定条目，再用 `restore` 恢复。账户与摘要可在 `data/sablelife_clipboards/<UUID>_<sha256>.nbt` 的文件名中找到，旧条目是 `<sha256>.nbt`。归档释放活动配额，数据仍留在磁盘上，恢复前对应物品不能粘贴。恢复受当前配额限制。同一账户重新复制相同内容可在配额内恢复它。

## 兼容与界面

- 可选模组适配按实际接口启用。LittleTiles 的渲染恢复匹配已支持的管线签名。使用 Toolgun 清理时，确认结构移除、原区域释放后才清除归属记录。可选接口无法接入时使用 Sable 原生清理。
- 修复切换招式、条件和目标来源后，未提交的输入可能落到其他设置的问题。绑定传感器时，目标对齐使用传感器的记忆时间，界面隐藏自己的记忆时长。

## 审查修复候选版

- `review.1` 保留降低配额前已保存的蓝图模板与待办。失败或取消的任务将待清理结构记入存档，确认结构永久删除后再解除归属。旧版 Photomancy 可以随服务端启动，蓝图适配仍需通过版本和接口检查。
- `review.2` 让 Move Set 先运行驱动所用传感器的招式表，同刻争用时沿用模块排序。延迟攻击各自跟踪来源招式，追踪动作使用本模块实际看见的最后位置。武器预览读取现有索敌状态，已经发射的追踪弹继续按自身寿命和追踪规则运行。默认零秒追踪激光沿用已发射光束的行为。
- 多个大型 Item Display 核心排队分片，大包仍采用现有格式。短时刷新中断后可用心跳恢复显示，长期断开或缓存淘汰后等待完整刷新。超过显示上限的保存模型依然可以在编辑器中清除或替换。
- Command Program 和 Sequence 的草稿跟随当前条目及版本。旧客户端可以浏览 Sequence，编辑需更新客户端。复制器在恢复归档时执行与粘贴相同的有界解码，复制失败提示会区分 2,000,000 字节压缩上限与 8 MiB 解码上限。
- `review.3` 会保留已登记的 Let it Walk 腿段清理任务。腿段卸载或停服重启后，任务会在腿段重新加载时继续处理。确认永久移除后再清除归属，已经归属新生命体的结构受到保护。旧存档按原有的腿段 UUID 继续追踪。
- 回退时使用对应版本的 JAR 和升级前的存档副本。
