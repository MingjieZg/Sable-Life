## Survival Heart Core and targeting

- The server setting `allowSurvivalHeartCoreTerrainBreaking` defaults to enabled. Turning it off preserves terrain and saved module settings while Survival Heart Core melee, lasers and blasts can still attack targets.
- With Line of Sight enabled, a target can be remembered for 0–60 seconds after it goes behind cover. The default is zero. Target Sensors check a player's chest and shoulders from their mark. Tracking lasers aim at the upper chest, adjusted for stance. Weapons check visibility from the actual muzzle.
- Target Alignment and Move Set can link to a Target Sensor on the same core. Inherited targets keep the source expiry across moves. Weapons can track the last visible position and apply their own line-of-sight rules before firing. Opening a preview leaves live targeting memory intact.

## Blueprints, Item Display and the Data Copier

- Existing Photomancy `.nbt` files can be placed directly. Sable Life restores the Heart Core modules, remaps their marks and fills in Item Display models with the official Photomancy installed. If a blueprint exceeds the tool's transfer limit, put the `.nbt` in the server's blueprint directory and run Photomancy's `/sablebp load`.
- Compatible clients can receive large Item Display snapshots in parts. Limits are 900 KiB per model and 64 models or 8 MiB per core, measured by uncompressed wire size and NBT read usage. Older clients can render the first part. Original models remain in the save.
- The Data Copier shows the stored size and the 2,000,000-byte compressed limit. It verifies that a configuration can be read back before copying it. World storage deduplicates by originating account, with quotas of 64 MiB per account and 2 GiB per world. Existing disk references remain usable.
- Operators can run `/sablelife clipboard status [<UUID|legacy>]` to check usage and `/sablelife clipboard archive <UUID|legacy> <sha256>` to archive a specific entry. Find the account and digest in `data/sablelife_clipboards/<UUID>_<sha256>.nbt`, or `<sha256>.nbt` for legacy entries. `restore` brings the entry back within the active quotas. Archived files still occupy disk space, and items referring to them cannot paste until they are restored. Copying the same content again from the original account can also restore it within the quotas.

## Compatibility and editors

- Optional integrations check the interfaces they use. LittleTiles rendering recovery matches supported pipeline signatures. Toolgun cleanup releases ownership records only after the structure and its plot are removed. Sable Life uses native Sable cleanup when the optional interface is unavailable.
- Switching moves, conditions or target sources no longer risks applying a pending edit to a different field. When Target Alignment follows a sensor, it uses the sensor's timer and hides its own retention field.

## Review candidates

- `review.1` retains saved blueprint templates and pending jobs when quotas decrease. Failed or cancelled jobs save pending removals and release ownership after confirming permanent removal. Older Photomancy versions can start with the server. The blueprint integration still requires the supported version and interfaces.
- In `review.2`, Move Sets evaluate tables that drive linked sensors first and keep authored order for actions with equal start times. Delayed attacks track their own source action, and tracking consumers use the last position they observed locally. Weapon previews read existing targeting state. Homing projectiles follow their own lifetime and tracking rules once launched. The default zero-second tracking laser keeps its existing behavior after emission.
- Several large Item Display cores queue their snapshots using the existing packet format. A heartbeat can restore display after a brief interruption. An expired or evicted view waits for a full refresh. Saved models over the display limit remain removable and replaceable in the editor.
- Command Program and Sequence drafts follow the selected row and server revision. Older clients can browse sequences and need an update to edit them. The Data Copier uses the same bounded decoder to restore and paste clipboards. Copy messages distinguish the 2,000,000-byte compressed limit from the 8 MiB decoded limit.
- `review.3` preserves queued cleanup for Let it Walk leg segments through chunk unloads and server restarts. Cleanup resumes when the segments load again and clears ownership after confirming permanent removal. Structures claimed by another creature are protected. Existing saves continue tracking legs by their recorded UUIDs.
- To roll back, use the JAR for the version you are returning to and your pre-upgrade world copy.
