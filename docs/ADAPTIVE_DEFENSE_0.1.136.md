# 全局高DPS自适应减伤（0.1.136）

## 位置与属性

Core settings首页或选项页点击Defense settings，也可翻到第5页。原死亡/消失页仍是第3/4页。

| 设置 | 默认与范围 |
|---|---|
| Adaptive damage reduction | 默认Off，整个生命体共用 |
| DPS threshold | 默认100 HP/s；0.1–100万 |
| Maximum reduction | 默认80%；0–95%，不允许100%免伤 |
| Detection window | 默认1秒；0.1–10秒，以游戏tick计时 |

页面显示当前输入DPS和当前自适应减伤百分比。创造模式可在生命体存活时调整；改配置会清除统计重新开始。

## 判定

普通攻击先通过已有装甲，再把剩余伤害交给这项全局防御，最后扣HP。所有攻击者、肢体与伤害类型共用同一份最近窗口伤害，不因切换武器/命中位置分别计数。

DPS = 最近窗口内被接受的装甲后伤害总量 ÷ 窗口秒数。超过阈值时目标减伤为1−阈值/DPS，再限制到设置的最大百分比。统计包含当前这一击；低DPS不减伤，爆发首击也不会被统计遗漏。拒绝伤害、完全被装甲挡下的伤害和回血不计。

减伤升高随滚动输入DPS连续变化；攻击减弱、旧伤害退出窗口后，保护按固定短缓冲平滑恢复，无需增加一个额外时间输入。统计使用自适应减伤前的数值，不会因实际掉血降低而反复开关。

例如阈值100 DPS，持续输入300 DPS，在1秒窗口稳定后约66.7%自适应减伤；输入更高时最多达到80%的默认上限。窗口填满前不是严格的累计伤害限额，而是逐渐形成保护。设置最大95%时，正常正伤害仍保留至少5%比例；极高HP下微小伤害会受可表示生命值精度约束，避免新增防御把原本可扣血的攻击舍入成免伤。

## 联动与存档

- 既有装甲、受伤Trigger、受伤音效、回血与Boss血条继续工作；后者反映实际扣血。
- 普通管理hurt命令也进入此防御；真正拆除核心走强制结束生命，不被这项减伤阻止。
- 配置保存/Photomancy复制，滚动伤害与实时减伤是临时战斗状态，不复制或保存。
- 激活、创造解除、卸载/重新载入，以及Arena强制归位满血时清除战斗历史，配置保留。
- 旧存档没有这项配置时默认关闭，原受伤行为不变。

## 实机示例

1. 将Boss HP设为足够高的值，例如5000。
2. Defense开启，阈值100、上限80%、窗口1秒。
3. 用低速攻击比较HP变化，观察DPS与减伤显示。
4. 用持续快速攻击观察输入DPS升高、掉血速度降低；停射后观察减伤逐渐恢复。
5. 换攻击者、攻击另一肢体，确认共享保护；检查受伤反击仍能触发。
6. 保存重进/复制配置，确认开关数值保留，但战斗统计从0开始。

自动验证：7项纯模型单元测试及5项集成测试通过，覆盖低DPS/关闭、当前首击、持续高DPS无反馈振荡、上限、平滑恢复、非法输入与队列有界、装甲顺序、跨肢体、存档复制、实时创造权限、Hurt、Arena/解除重置、核心结束生命和高HP精度。GUI scale2/3独立客户端截图已检查。

最终构建与合并游戏测试55/55通过；包括防御、Melee、标记、控制、音效和生命周期。

## 三个数值如何搭配（0.1.137提示补充）

- 阈值决定保护从哪里开始，调低更强；不是单次伤害封顶。
- 上限决定最多减多少，不会一直固定减80%；0表示不减伤。
- 窗口决定如何计算DPS：伤害总量除以秒数。短窗口对短爆发更敏感、忘记较快；长窗口起效较缓、旧伤害保留较久；不是无敌时长。

默认100阈值、80%上限、1秒窗口的稳定例子：80输入DPS不减；200输入DPS减50%剩100；500输入DPS减80%剩100；1000输入DPS触及80%上限，剩200。窗口尚未填满及停火恢复期间数值会变化。这些解释已加入独立悬停提示和页面常驻示例。
